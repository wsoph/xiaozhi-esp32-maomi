## 2. 真实时间顺序

1. 接手后先按 handover 检查 RC3 的未提交修改、构建状态和工具链状态，继续未完成的编译与最终复核，没有重做 RC2 备份或已完成的旧工作。
2. RC3 达到可刷写状态后，用户先检查功能列表，再明确授权刷机。刷机不是全自动完成：用户多次手动进入下载模式、按住 BOOT、重新插拔连接线；设备最终进入猫咪界面。设备没有独立 RESET 键，过程中使用了 BOOT 和重新插拔操作。
3. 第一轮真机互动结果：
   - 摸摸出现被摸动画，但没有独立猫叫。
   - 喂食出现进食动画，但没有独立猫叫。
   - 陪玩先出现哭的 AI 表情，再出现玩耍动画，之后停留在玩耍动画；同一阶段还观察到有时需要重复说几次才有回应。
4. 对照 handover 中的实现，用户确认延迟来自最长 15 秒的猫叫等待，并决定所有互动都不需要独立猫叫。随后取消这段等待和互动猫叫，而不是继续修复猫叫排队方案。这一修改直接推翻了 handover 中尚待真机验证的 RC3 猫叫设计。
5. 再次刷写后，摸摸和喂食动画正常；陪玩会先显示大笑表情，再进入玩耍动画。用户询问喂食为什么没有相同的前置 AI 表情，要求只解释原因、不改代码；随后继续测试其他功能。
6. 状态查询能够正常语音回复亲密度 7、电量 73%。这是一次具体真机观察，不代表所有亲密度、电量边界均已验证。
7. 倒计时最初可以设置并显示剩余 0 秒，但在聆听状态到点时不播放声音和动画；待命状态则能正常提醒。用户明确要求聆听中和说话中也必须优先提醒，并要求设置后全屏显示 `HH:MM:SS`、逐秒递减。
8. 用户同时确认不需要 AI 字幕；无倒计时时显示猫咪表情，有倒计时时全屏显示时间。视觉方向经过白猫、橘猫、有耳、无耳等选择，最终确定为 240×240 橘色满屏无耳版，不保留顶部电量和网络图标，并增加电量降至 20% 时的一次语音充电提示。
9. 新视觉和相关固件刷入后，用户反馈“效果很好”。随后提出两项调整：删除体验不佳的“不许说是/不是”游戏；把此前记录的其他四种游戏补齐。最终形成六种游戏：猫咪猜心、三分钟冒险、故事接龙、猫咪小侦探、记忆旅行箱、快问快答。
10. 倒计时页面又提供多个橘猫元素方案，用户选择 B 方案“无耳橘猫脸边框”。用户授权后再次进入下载模式完成刷写。本 session 可见记录没有用户对这次刷写后的 B 方案逐项验收结论。
11. 后台人设根据最新功能更新：开始玩游戏时先说出可选游戏让用户选择；被问“有哪些功能”时介绍新增的猫咪互动、游戏、提醒、倒计时等能力。人设文本已记录在仓库文档中；本 session 未确认网页后台最终保存后的线上版本号或截图。
12. 核心版本完成后，代码被整理、提交、打标签并同步到公开 Fork。为避免公开提交邮箱，用户在 GitHub 页面完成邮箱隐私设置；具体邮箱、账号凭据和登录信息不在本底稿记录。
13. 后续核心补丁依次加入：双击音量上键触发摸摸；提醒可中断聆听和说话，不再只在待命状态生效；新增专门的聆听动画。用户选择聆听表情第一版，明确授权刷机并完成 BOOT 等人工操作，之后反馈测试通过。
14. 上述补丁提交后合并到 `main`。同步期间曾出现 GitHub Git 通道暂时不可达，本地与远端提交不同步；用户重新连接 VPN 后重试，最终 `main` 与远端合并提交一致。随后正式源码仓库与本地归档、构建资料目录被分开整理，并生成下一功能 session 的交接文件。

## 3. 本 session 实际完成或验证的功能

### 唤醒词“猫咪过来”与猫叫

- 当前状态：部分完成。
- 做了什么：保留自定义唤醒词和本地唤醒回应能力；对互动猫叫方案进行了真机复测。RC3 原本尝试等待独立猫叫进入播放队列，真机仍没有听到该猫叫，且最长 15 秒等待影响后续响应，因此按用户决定删除互动中的独立猫叫和等待逻辑。
- 如何验证：用户分别触发摸摸、喂食和陪玩，三者都显示对应动画但没有独立猫叫；用户随后确认互动不再需要猫叫。
- 实际效果：摸摸、喂食、陪玩不再以独立猫叫作为完成条件，避免等待猫叫阻塞后续语音。唤醒本地音频文件仍存在于板型资源中。
- 限制：本 session 可见记录没有单独复测并确认“猫咪过来”的识别率，也没有明确记录本地唤醒回应音频是否实际播放；这两项本 session 未确认。素材来源与公开使用权也未核验。

### 猫咪表情

- 当前状态：完成核心视觉并有部分真机验证。
- 做了什么：为 1.54 英寸、240×240 方屏制作满屏橘猫静态表情和动态动画；去掉画面中的耳朵，不显示顶部网络、电量图标或 AI 字幕；增加摸摸、喂食、玩耍、睡眠、提醒、充电、低电量、眨眼、聆听等动画。倒计时采用 B 方案的无耳橘猫脸边框。
- 如何验证：新视觉刷入后，用户反馈整体“效果很好”；摸摸、喂食、玩耍动画均在真机出现。聆听动画第一版在后续补丁刷入后，用户反馈测试通过。
- 实际效果：无倒计时时显示橘猫表情；有倒计时时由全屏倒计时层优先显示。陪玩仍会先出现 AI 返回的大笑等表情，再切换到本地玩耍动画，这一顺序在本 session 被观察并保留。
- 限制：不是每一张静态表情、每一个动态 GIF 都逐项做了真机验收；B 方案倒计时页面刷写后没有留下明确的单项验收反馈。外壳尚未设计，画面无耳只是为未来实体耳朵留出视觉空间，不能写成外壳成品。

### 摸摸互动

- 当前状态：完成并通过真机验证。
- 做了什么：保留自然语言摸摸互动，取消独立互动猫叫；后续增加“双击音量上键＝抚摸”。
- 如何验证：第一轮刷机后用户看到被摸动画；取消猫叫等待并重刷后，用户确认摸摸动画正常；加入按键补丁、提醒抢占和聆听动画后再次刷机，用户反馈整体测试通过。
- 实际效果：语音触发可显示被摸动画，双击音量上键也可触发摸摸；互动会按现有规则增加亲密度，不依赖独立猫叫结束。
- 限制：本 session 没有记录长时间连续双击、按键抖动、极短/极长双击间隔等压力测试数据。

### 喂食互动

- 当前状态：完成并通过基本真机验证。
- 做了什么：保留喂食工具和进食动画，取消独立互动猫叫。
- 如何验证：用户触发喂食后两轮都观察到进食动画，第二轮明确反馈喂食动画正常。
- 实际效果：喂食会进入本地进食动画，不播放独立猫叫。与陪玩不同，测试时没有先出现一段 AI 表情再进入喂食动画。
- 限制：本 session 只验证了基本触发和动画，未记录连续喂食、异常网络、重启后亲密度持久化等边界测试。

### 语音游戏

- 当前状态：功能实现完成，六种游戏的逐项真机验收未完成。
- 做了什么：以“陪我玩”“我们一起玩”等自然语言作为入口，由联网 AI 先介绍游戏并让用户选择；单局目标为 1–3 分钟，面向 10 岁儿童和成年人，以娱乐陪伴为主，也可包含轻量学习。体验不佳的“不许说是/不是”被删除，最终保留六种游戏。
- 如何验证：用户实际体验了“不许说是/不是”并据此决定删除；新游戏清单、设备工具接口和人设流程已写入代码及文档。现有 Git 历史和主机测试覆盖游戏工具契约。
- 实际效果：设备端负责成功开局时播放一次玩耍动画、记录一次陪玩亲密度；后续回合、内容生成和结束由联网 AI 对话控制。
- 限制：本 session 可见记录没有六种游戏各自完整玩完一局的真机证据，也没有离线场景验收；因此不能把六种游戏全部写成已逐项现场验证。
